# Conformance harness

The spec requires every normative statement to have executable test vectors
covering: canonical identity, static validation, deterministic execution,
structured errors, replay, state recovery, capability rejection, module
activation, and compatibility/semantic diffing.

The vectors are the crate tests plus end-to-end on-device runs, driven by
`make test` / `make ci`. This file maps each spec conformance dimension to the
tests / on-device proofs that cover it, so coverage is auditable. Every artefact, the
composition, byte-serialization encoders, and the authored→device packaging path
are covered below.

(see `docs/bytecode_policy.md`).

## Placement

Retries and compensation are host-only deliberately. A device stage is pure
compute: re-running one that failed yields the same failure, and there is no
effect to undo, because on device an effect is a separate connector `.fmod`
wired into the graph. Retry and rollback therefore belong to the graph and to
the connector that owns the external interaction. Implementing them in the
device executor would give a deployment the appearance of durability with none
of the mechanism.
